# Mobile Kitchen — キッチンカー出店プラットフォーム

キッチンカーの **出店募集（主催者）** と **出店申込（出店者）** をひとつの画面にまとめた Web アプリです。
出店者はイベントをスワイプで見て、その場で申し込めます。主催者はイベントを公開し、申込を受け取り、
募集案内のメール文面をワンタップで生成できます。

- 📱 スマートフォン前提の UI（スワイプ + タップ）
- 🎨 引き算のデザイン / ライト・ダーク対応
- 🗂 ログイン不要で出店申込、主催者のみログイン
- ☁️ バックエンドは差し替え可能（端末内 IndexedDB ↔ Supabase）

---

## 画面

### 出店者ページ `#/vendor`

| 機能 | 内容 |
| --- | --- |
| さがす | 募集中イベントをカードデッキで1件ずつ表示。**右スワイプ = 申し込む／左スワイプ = 見送る／タップ = 詳細**。誤操作は「戻す」で1件ずつ取り消せます |
| 申込フォーム | 6ステップ（店舗情報 → 火気 → 電気 → 出店内容 → 書類 → 確認）。横スワイプでもステップを移動できます |
| 申込状況 | 自分が申し込んだイベントと、確認待ち／承認済みの状態を一覧 |

入力内容は端末に保存され、**2回目以降の申込は自動入力されます**。

### 管理者ページ `#/admin`

| タブ | 内容 |
| --- | --- |
| イベント | 一覧・新規作成・編集・公開/締切の切替・削除。申込数と充足率をその場で確認 |
| 出店者 | 申込の一覧・検索・詳細・承認/見送り・**CSV書き出し**（消防署提出や台帳作成にそのまま使えます） |
| メール | **募集中イベントを複数選んで、案内メールの文面を自動生成**。4種類のテンプレートから選択、その場で編集してコピー |
| 設定 | データ保存先（端末内 / Supabase）の切替、スキーマSQLのコピー、外観（自動/ライト/ダーク） |

## 収集する情報

### イベント（主催者が入力）

タイトル / 概要 / サムネイル画像（任意） / 開催日時 / 営業時間 / 搬入時刻 / 会場名 / 住所 /
出店料・補足 / 電源の有無・1区画の供給上限(W) / 給排水 / 募集台数 / 想定来場者数 / 申込締切 /
主催者名 / 問い合わせ先 / キャンセルポリシー / 備考 / 添付資料（PDF等） / 公開状態

### 出店申込（出店者が入力）

- 店舗名 / 代表者名 / メールアドレス / 電話番号
- 火気使用の有無
  - ガスの場合：種類（プロパン / カセットボンベ / その他）・本数・1本あたり容量
  - 炭の場合：**消火方法**
  - 消火器の携行本数
- 電気を使用する機器（**名称・消費電力・台数を機器ごとに追加**、合計Wを自動計算し会場の上限超過を警告）
- 発電機の持込有無・機種
- 提供メニュー（名称・価格、複数追加可）
- キッチンカーサイズ（全長・全幅・全高／**展開時**の全長・全幅）
- 車両ナンバー / 食品営業許可番号 / PL保険の加入有無
- ファイル添付（免許証・車検証・営業許可証など、PDF/画像）
- 主催者への連絡事項

> 元の要件に加えて、**消火器の本数・発電機・展開時サイズ・営業許可番号・PL保険・搬入時刻・想定来場者数・キャンセルポリシー**
> を追加しています。いずれも現場で毎回聞き直しが発生しやすい項目です。

## UI の設計意図

Apple 的な「引き算」を土台に、行動経済学の知見を申込導線へ落としています。

| 仕掛け | 置き場所 | 狙い |
| --- | --- | --- |
| 1画面1イベントのカードデッキ | さがす | 選択肢を並べるほど人は決められなくなる（選択のパラドックス）ため、判断を右か左かに単純化 |
| 「残り◯枠」「締切あと◯日」 | カード・詳細・申込 | 希少性と締切効果 |
| 「◯店舗が申込済み」「想定来場◯千人」 | カード・詳細 | 社会的証明と、判断に効く数字の先出し |
| 充足率バー | カード・管理一覧 | 数字より「あとどれだけ残っているか」が直感的 |
| 「戻す」「やっぱり見る」 | 見送り直後 | 取り消せると分かると、人は決断に踏み切れる |
| ステップ進捗と「あと◯ステップ」 | 申込フォーム | 目標勾配効果。残りが見えるほど完走率が上がる |
| キャンセルポリシーの明示 | 詳細・最終確認 | 損失回避の緩和 |
| 完了アニメーション + 次の行動 | 申込完了 | ピーク・エンドの法則 |
| 入力内容の自動保存 | 全体 | 2回目以降の摩擦をほぼゼロに |

配色は面＝白・線＝極細・色は1色（アクセント）に限定し、強調は色ではなく余白と階層で作っています。

## データの保存先

### 1. 端末内（既定）

設定不要でそのまま動きます。イベントと申込はブラウザの IndexedDB に保存されるため、
**その端末の中だけ**で完結します。デモ・動作確認・単独での下書き作業向けです。

### 2. Supabase（複数人で共有する本番運用）

主催者の端末で出店者の申込を受け取るには、こちらを設定してください。所要 5 分・無料枠で運用できます。

1. [supabase.com](https://supabase.com) でプロジェクトを作成
2. 管理者ページ → **設定 → スキーマSQLをコピー** して、Supabase の SQL Editor で実行
   （テーブル・インデックス・RLS ポリシー・ストレージバケットが作られます）
3. Supabase の **Authentication → Users → Add user** で主催者アカウントを登録
4. Supabase の **Project Settings → API** の `URL` と `anon public` キーを、管理者ページの設定に貼り付けて「接続して再読み込み」

以後、管理者ページはそのメール／パスワードでログインします。

権限の設計:

- 公開済みイベントは誰でも閲覧可（下書きは主催者のみ）
- 出店申込は誰でも送信可、**閲覧・承認・削除は主催者のみ**
- 添付ファイルは `attachments` バケットに保存

GitHub Actions のシークレット (`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`) に設定しておけば、
ビルド時に埋め込まれ、利用者側での設定は不要になります。

## 構成

```
src/
  lib/
    types.ts          ドメインモデル
    db/               データアダプタ（契約 / IndexedDB / Supabase）
    store.tsx         React コンテキスト。取得と更新を集約
    format.ts         表示整形と、残枠・締切などの導出ロジック
    mailTemplate.ts   複数イベント → メール文面の生成
    csv.ts            申込のCSV書き出し
    schemaSql.ts      Supabase スキーマ定義
    seed.ts           初回起動時のサンプルデータ
  components/         UIプリミティブ、シート、トースト、イベントカード
  pages/
    Landing.tsx
    vendor/           さがす（デッキ）/ 申込フォーム / 申込状況
    admin/            イベント / 出店者 / メール / 設定
```

バックエンドは `DataAdapter` の 1 インターフェースに閉じているので、
Supabase 以外（Firebase、自前 API など）へ差し替える場合も実装を 1 ファイル足すだけで済みます。
